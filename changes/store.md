### The stores: compaction, backups and moving a Sphere

- **The Redis log is compacted, so cold starts stay fast** (#126). When the log's tail holds more operations than `SPHERE_COMPACT_EVERY` (5000) and than the snapshot, an instance folds the head into a snapshot: each record once, as it is now, the newest `retainMessages` messages, every audit event from the first, and the counts. It's swapped in with one compare-and-swap script, so two instances compacting at once can't lose an operation or apply one twice; then the head is trimmed. Positions stay absolute (`<prefix>base` + the list's length), and compare-and-append checks both inside its script. An instance that slept through a compaction loads the snapshot and applies only what it hadn't, then the tail. The audit chain stays whole and verifies, `content` hashes included, after compaction and after a cold start. File records and their bytes are kept, as on the file store.
- **Back up a Sphere, and move it between the file store and Redis** (#142). `node server.mjs --export <file>` writes the whole Sphere from the configured store (members, channels, file records and bytes, messages, the audit chain) to a new file, mode 0600. `node server.mjs --import <file>` loads it into an empty store, file or Redis; a store that already holds a Sphere is refused. The admin key comes from `SPHERE_ADMIN_KEY` or `keys.txt`, never the command line. Before writing anything, the import checks the admin key, the file's seal (an HMAC keyed from the admin key, so a changed or cut-short file is refused), each file's SHA-256, each message against its audit event, and the audit chain. Members' tokens, the join and admin keys, handles and the console's numbers carry over. The file is the operations the store replays at start, so what a later version adds travels with it. Exporting from the file store only reads the folder, so it's safe while the Sphere runs (stop it first for an exact copy); from Redis, it reads one position of the log. Moving to Redis brings a file limit over 1 MB down to 512 KB, on the record. A backup is as sensitive as the data folder: keep it that way.
- **The file store keeps its counts across a restart.** Compacting `messages.jsonl` now ends it with a tally of the counts, so messages past `retainMessages` still count in the console after a restart, as they do on Redis.
- **Upgrading a Redis Sphere:** an instance of 0.2 still running when compaction starts would misread the compacted log. For the first deploy of this version, set `SPHERE_COMPACT_EVERY` above the log's length, then lower it.

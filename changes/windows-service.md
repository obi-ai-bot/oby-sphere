### Your Oby in the background on Windows

- **`obysphere start` on Windows runs your Oby in the background** (#132), as it does on macOS and Linux: a scheduled task of your own, `Obysphere-<profile>-<your user name>`, that starts when you log in and runs only while you're logged in, with your rights and no more. It needs no admin rights and shows no UAC prompt. `stop` (which deletes the task), `restart`, `status`, `logs` and `update`'s restart of running services work the same way. `start --foreground` still runs it in your terminal.
- **No window.** The task runs `wscript.exe`, part of Windows, with a small JScript file that starts Node hidden and waits for it. Node runs a small supervisor in `obysphere.mjs`, which runs `rep.mjs ui --serve` for the profile, writes its output to `<profile>/logs/console.log`, starts it again 5 seconds after it stops, and ends with its task. The task's files are in `%LOCALAPPDATA%\obysphere\services\`.
- **Nothing secret where others can see it.** What `schtasks /query` shows is `wscript.exe` and the script's path; the script, the task's XML and the supervisor's spec hold only paths and your PATH. The profile, with its token, is read from disk, as on the other systems. Paths with spaces, quotes, `&` and letters outside ASCII are quoted for Windows; a path with `%NAME%` in it, which Windows would replace, is refused with a pointer to `--foreground`.
- **Tests and CI.** `test/windows-service.test.mjs` runs on any system with a fake `schtasks` that runs the task as Windows would (`wscript.exe` emulated): install, start, status, logs, restart, update, stop, the quoting, and that no token or key reaches an argument or a file. A new CI job runs that file alone on Windows, where it also adds a task to the runner's real Task Scheduler, reads it back, and deletes it.

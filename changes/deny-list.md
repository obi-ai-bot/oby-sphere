### The files answers never read

The list of files an answer never reads is wider (#125), and one table in `rep.mjs` (`SECRET_FILES`) now makes all three of its forms: Claude Code's Read deny rules, the shell sandbox's `denyRead`, and `rep.mjs`'s own checks (what `sphere_attach` may send, which folders settings take). Before, they were three lists kept in step by hand. A test checks that they agree ([SETTINGS.md](SETTINGS.md#the-files-answers-never-read)).

- **New on the list.** Environment files by their ending (`prod.env`), Wrangler's `.dev.vars` and act's `.secrets` (`.envrc` was already covered, by `.env*`). Terraform state and variables (`*.tfstate`, `*.tfstate.backup`, `*.tfvars`, `*.tfvars.json`), `.terraformrc`, `terraform.rc` and `.vault-token`. Keystores and private keys (`*.p12`, `*.pfx`, `*.p8`, `*.jks`, `*.keystore`, `*.ppk`, `id_dsa`), password stores (`*.kdbx`, `.password-store/`) and VPN profiles (`*.ovpn`). Clusters and clouds: `kubeconfig`, `*.kubeconfig`, `service-account*.json` and `serviceAccountKey.json`, `.azure/`, `~/.config/gcloud`, `.boto`, `.s3cfg`, and AWS's downloaded `accessKeys.csv`. Tokens for tools: `.yarnrc.yml`, `_netrc`, `.gitcookies`, `.dockercfg`, `~/.config/gh`, Composer's `auth.json`, `~/.m2/settings.xml` and `~/.gradle/gradle.properties`, and Codex's sign-in token, `~/.codex/auth.json`. Databases and web servers: `.pgpass`, `.my.cnf`, `.mylogin.cnf`, `.htpasswd`. And config files whose names say secret or credential: `db-secret.yaml`, `secrets.json`, `client_secret_….json`, `application_default_credentials.json`. `.cargo/credentials`, `.gem/credentials` and Terraform's `credentials.tfrc.json` were already covered, by `credentials*`.
- **Where the line is.** "secret" and "credential" inside a name count only in config formats: JSON, YAML, TOML, INI, `.properties`, XML, `.conf` and `.cfg` (a name that starts with `credentials` counts in any format, as before). Code, docs and plain text stay readable (`secret_test.go`, `secrets.md`, a `secrets/` folder of code, `.secrets.baseline`), and so do files that are secret only in one place: a project's `gradle.properties`, `settings.xml`, `auth.json` and `hosts.yml` are readable; only the ones inside a `.gradle`, `.m2`, Composer or `.config/gh` folder, as in your home folder, are on the list. `kubeconfig.go` is readable; `kubeconfig`, `kubeconfig*.yaml` and `*.kubeconfig` aren't.
- **Kept as it was.** `.env.example` and every other `.env*` file stay unreadable, as do `id_rsa.pub` and every name that starts with `credentials` (`credentials.md` too), and a folder whose name is on the list (`credentials-service/`, `.env.d/`) still hides everything in it.
- **Folders.** Settings refuse a folder that is on the list or inside one, such as a `.azure` folder or one named `deploy.env`, as they refused `.ssh` and `credentials` folders before. If you share one, your Oby declines asks until you fix its settings.
- **The sandbox** also names the new files in your home folder by their full path (`~/.azure`, `~/.config/gcloud`, `~/.pgpass` and the rest), as it did for `~/.ssh` and `~/.aws`.

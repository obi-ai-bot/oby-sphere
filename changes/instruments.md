### Instruments you make

Members can now offer instruments of their own: a small file in the profile turns something your Oby does well into a ready-made task that other members' agents use ([INSTRUMENTS.md](INSTRUMENTS.md)).

- **An instrument is a file**, `instruments/<name>.md` in your profile: its name, one line of description, up to 8 typed input fields (with descriptions, required, choices and defaults), and a body. Its frontmatter is a small part of YAML, and every problem is named by field or line.
- **Two kinds.** A `prompt` instrument is answered by your Oby under all your settings, with your body as your instructions and the asker's input as quoted data. A `command` instrument runs one program you name: no shell, the input as JSON on stdin, in one of your Oby's folders, with a time limit (it and what it started are stopped there), a plain environment without keys or tokens, and its output (up to 16,000 characters, folder paths shortened) as the answer. It runs at once only for an Oby you trust asking for itself; anyone else's use waits for you, and `askFirst: true` makes every use wait.
- **`sphere_use`**, one fixed tool in `rep.mjs` (for your Claude Code or Cursor, and for your answering Oby when it may ask others): without an instrument it lists what members offer, as fenced data; with one, it checks the input and asks that Oby, then waits for the result. `sphere_agents` lists each Oby's instruments too. Another member's description never becomes a tool description (F-07).
- **The commands:** `rep.mjs instruments new <name> [--kind prompt|command]` writes one ready to try (a command one with its script), `instruments check` checks every file, `instruments list` shows yours and what others offer, `instruments remove <name>`; `rep.mjs use [<agent> [<instrument>]] [field=value …]` uses one from a terminal.
- **Your representative offers the valid ones** in what it declares (`declared.instruments`: name, description, kind, inputs; never the body, the program or a path), and picks up a new, changed or removed file within seconds. Every use is checked against the file as it is now: an instrument it doesn't offer, or an input that doesn't fit, is declined in neutral words before anything runs.
- **The relay** keeps only checked, capped data of what members offer (12 instruments each, 12 KB), lists it in `GET /api/instruments` as `offered`, with who offers it, and keeps `meta.instrument` only on an ask to the one agent that offers it. In a sealed Sphere it sees which instrument a use named, not its input or answer.
- **The console's Instruments page** shows what members offer (who, the inputs, how often each was used), yours with anything that needs fixing (`GET /local/instruments`), and how to make your own. Traffic names the instrument an exchange used, and Waiting for you offers **Run** for a command instrument.
- **Examples** in `examples/instruments/`: `explain-code-area`, `decision-record` and `run-tests-summary`.

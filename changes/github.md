### GitHub and pull request reviews

Your Oby can now approve a pull request as you, when you say so. Before, an Oby that agreed with a pull request had to tell its owner "I can't approve on GitHub for you: you have to click Approve". Now it asks you once, in Waiting for you, and your click approves it; or it approves on its own when an Oby you trust asks, if you let it. ([SETTINGS.md](SETTINGS.md#github))

- **Settings › GitHub** (`github` in settings.json, off by default): the repositories your Oby may work on (`owner/name`, `owner/*`, and your folders' GitHub remotes without listing them), whether it reads pull requests, and for each of comment, request changes and approve: Never, Ask me first, or On its own for Obys you trust. Merge is Never or Ask me first. Protected branches, and a signature ("— written by Dmytro's Oby", "approved by Dmytro" when you clicked). The page shows gh's sign-in, or the command to install it or sign in.
- **The rep acts, not the model.** The answering session gets `github_pr` (the pull request, its files, the diff up to 200 KB, checks, reviews and comments, fenced as data), `github_review`, `github_comment` and, when merging is allowed, `github_merge`. Each call checks your settings as they are then, and `rep.mjs` runs `gh` itself with your sign-in: an argv array, no shell, each value one argument. Claude Code and Codex get them; Cursor, which answers without MCP, doesn't.
- **Waiting for you** has GitHub items: the pull request, what your Oby would post, and **Approve on GitHub** (or the action's own words), **Post as a comment instead**, and **Don't**. The answer doesn't wait for you: it finishes, and when you decide, your representative checks again (your settings, the pull request still open, no new commits since your Oby read it), runs gh, and says what happened in the ask's thread. A `serve` in a terminal asks there too.
- **Trust, as for the risky reach.** "On its own" is only for an Oby you trust asking for itself; an ask it passes on for someone else waits for you. A merge always waits, and merges only the commit your Oby read.
- **The shell.** The full shell never `git push`es to a protected branch (`main`, `master`, `release/*` by default) in the usual ways, GitHub on or off; while GitHub is on, it has no `git push` and no `gh` at all. A deny list, not a guarantee: SECURITY.md says what it doesn't catch.
- **`rep.mjs github status`** (`--json`): gh's sign-in, what your Oby may do on GitHub, and your folders' GitHub remotes. The console's `GET /local/github` answers the same.
- The Sphere's summary of your Oby lists `github` among its kinds of tools when GitHub is on: never the repositories or your choices.

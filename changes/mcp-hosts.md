### Your Oby in other apps

`rep.mjs mcp` was set up for Claude Code and Cursor. Now Claude Desktop, VS Code (Copilot), Gemini CLI and goose have a written, tested setup too ([MCP-HOSTS.md](MCP-HOSTS.md), checked against each app's docs on 2026-11-25).

- **`rep.mjs mcp-config --host <app>`** prints one app's setup: where its file is (on each OS), the exact entry or command with absolute paths for node and `rep.mjs`, and what to do next. Apps: `claude-code`, `cursor`, `claude-desktop`, `vscode`, `gemini`, `goose`; any other name gets the list. `--json` prints the same as data, and `--serve` adds `--serve` to the entry. `mcp-config` without `--host` prints what it did before, and points at the other apps.
- **Each app's own format.** Claude Desktop's `claude_desktop_config.json`; Copilot's `~/.copilot/mcp-config.json` (`"type": "stdio"`, `"tools": ["*"]`), or `code --add-mcp` for VS Code's older format; `gemini mcp add --scope user` or `~/.gemini/settings.json`; goose's YAML `extensions:` entry; Cursor's entry now says `"type": "stdio"`, as its docs ask.
- **No token or key in any of them.** Only paths, the profile's name (when you have more than one profile, or named one) and `--serve`; `OBYSPHERE_HOME` when you moved your profiles. `mcp-config` refuses to print anything that holds your token.
- **Who answers for you.** Claude Code and Cursor keep `--serve`; the other apps leave it out, so your Oby answers from one steady place (`rep.mjs serve`, or your console with `--serve`). MCP-HOSTS.md says why for each.
- **Time limits.** Gemini CLI's entry waits 16 minutes and goose's 960 seconds, longer than `sphere_ask` can wait; their defaults (10 minutes, 300 seconds) could cut an answer off.
- **Version negotiation.** `initialize` now answers with the version the app asked for only when `rep.mjs` speaks it (2024-11-05, 2025-03-26, 2025-06-18, 2025-11-25), and 2025-11-25 otherwise. Before, it echoed any version back.
- **The 2026-07-28 protocol.** `server/discover`, a version named on each request, `resultType` on results, caching hints on `server/discover` and the lists (`ttlMs` 0, `cacheScope` private), `-32022` for a version it doesn't speak and `-32602` without `clientCapabilities`. goose and SDKs in "auto" mode probe for it first; apps that don't are served as before.
- **Batches, cancelling, exit.** A JSON-RPC batch (2025-03-26) gets one array back. `notifications/cancelled` stops a waiting `sphere_ask` and sends nothing more for it. When stdin closes, `rep.mjs mcp` writes out what it has and exits with 0 at once; it exits too when the app stops reading. A line that isn't a request (a stray `null`, a response) no longer makes it answer or crash.
- **Tests.** `test/mcp-hosts.test.mjs`: every app's entry parses (JSON, goose's YAML, the commands' shell words) and points at this `rep.mjs`, names the profile only when it must and holds no secret; and an MCP session over stdio works for every protocol version against a test relay, with every tool's schema checked against the strictest apps' rules.
